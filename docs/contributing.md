# Contributing
Please add a failing evaluation case before changing publication rules. Do not weaken a blocker to make a draft pass. Every validator change needs a test showing a valid case and an invalid case. Add meaningful topic-specific SVG examples rather than ornamental flowcharts. Keep source-audit optional, preserve provenance, and never commit fabricated measurements. Run `python -m unittest discover -s tests -v` and `python evals/evaluate.py --suite evals/cases.json --root evals/fixtures`. Before release collect at least three independent model outputs per topic and report variance, failure types and reviewer notes.
