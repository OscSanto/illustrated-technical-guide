# Provenance standard
Read `provenance.md` for the full schema and prior fidelity rules. Every visible figure, math derivation, code/pseudocode, data table, API example and reported metric must be labeled as source reproduction/adaptation, independent verification, our derivation/implementation, hypothetical or unverified. "Our implementation · Pseudocode" must never be passed off as the source's code. Official API requires a verified version, endpoint, fields and docs URL. Benchmark numbers require provenance and test environment. A structural provenance gate detects unsupported metadata but cannot perform factual peer review. In source-audit mode, every critical item receives explicit coverage disposition and faithful comparison.
