# Hands-on / first-success tutorial
Use for databases, frameworks, tooling, deployment, build systems and languages where the learner needs to **do** something.

## Required progression
1. State OS/tool versions and prerequisites; choose smallest reliable path and note alternatives briefly.
2. Achieve a verifiable first result quickly (aim ~15–30 minutes, not a hard limit). Provide exact commands, expected output, a checkpoint, and a common failure/recovery path.
3. Grow one dataset/project across milestones. Each milestone supplies: goal, action, runnable code, observable output, why it works, diagnostic when it fails, and short independent exercise.
4. Cover operational gotchas (paths, authentication, permissions, resource costs, cleanup) when relevant.
5. Advanced material follows working fundamentals; do not turn all chapters into equation-heavy explanations.
6. Test commands against the actual named engine/version. PostgreSQL queries must be run in PostgreSQL, not silently substituted with SQLite.

## Acceptance
A learner can reproduce the expected milestone results from a fresh environment; failures show a realistic fix; `RUN_LOG.json` records tests and environment. If execution unavailable, mark untested and block publication claims.
